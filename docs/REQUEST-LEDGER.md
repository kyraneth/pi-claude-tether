# Request measurement ledger

The package state directory's `retire.log` (exact path in README: `$XDG_STATE_HOME/<package>/...`, `~/.local/state/<package>/...` without XDG_STATE_HOME) is now a **metadata-only JSONL ledger**. Existing untyped retirement rows remain readable; new rows have a `type`. The file is created and corrected to mode `0600`. One ordered asynchronous, best-effort append owner serves all row types; a request never awaits disk. There is no rotation, size cap or token limit.

## Rows and joins

Every row includes `at` (UTC observation timestamp), `processId` (adapter-minted UUID), CLI `pid`, `piSessionId`, `cliSessionId`, `requestedModel`, `episodeId`, `triggerMode`, and `spawnCause`. Missing observations are `null`, **not zero**. An episode is one adapter stream call; a tool handoff ends one episode and the next Pi call attaches another to the same process.

- `process_spawn`: byte lengths of the actual UTF-8 system-prompt file contents (`systemPromptBytes`) and staged MCP tool-schema JSON file (`toolSchemaBytes`). An unavailable/verbatim external schema is unknown (`null`). These are offered file payload sizes, **not Anthropic wire sizes or token counts**. The schema is recorded once at spawn, not resummed per request.
- `process_init`: physical `model` and `session_id` reported by CLI initialization (`physicalModel`, `reportedCliSessionId`), when present.
- `episode_start` / `episode_end`: episode boundaries. Trigger is `spawn`, `turn` or `handoff`; it does not infer what caused Pi to call the adapter.
- `request`: exactly one row for each top-level `message_start` through `message_stop`. Nested `parent_tool_use_id` streams are excluded. `physicalModel` comes from `message_start.message.model`. `requestId` is an adapter UUID, not an Anthropic HTTP request ID. `usage` includes `input`, `cacheRead`, `cacheWrite`, `output`, `cacheWrite1h`, `cacheWrite5m`. Start usage is replaced only by fields actually emitted in `message_delta`; counters are never added within a request. Missing tier breakdowns stay null.
- `result`: raw CLI envelope counters projected into `usage`; separately, `cumulativeModelUsage` contains each model's process-cumulative counters and cost. `totalCostUsd`, `numTurns`, and `reportedCliSessionId` are preserved. **Never add result usage, cumulative model usage, or results from successive turns to request rows.** To measure process-cumulative change, difference successive cumulative snapshots. Result model totals can include CLI auxiliary model calls not exposed as top-level requests.
- `rate_limit`: emitted utilization fraction, `windowType`, `resetsAt`, status and overage metadata. Missing utilization stays null. Older recorded streams omit it; persistence cannot create the missing signal. No allowance-percent estimate is fabricated. Concurrent account use confounds episode attribution; a window switch/reset breaks any utilization delta. Claude subscription percent is not additive with another subscription's percent or API dollars.
- `retire`: `reasons`, including launch-signature/history changes, thinking-control failure, keepalive disabled/expiry, cache expired/`cache_expiry` (the parked lifetime follows the observed cache TTL), handoff wait expiry, no Pi session, result/episode errors, unconfirmed steer consumption (`steer_unconfirmed`), failed steer write (`steer_write_error`), resume miss, abort, inactivity, agent-wait expiry, stdout closure, process exit, pool replacement and exact lifecycle event names (`model_select`, `session_compact`, `session_tree`, `session_shutdown`, `session_start`, `beforeExit`). Signature values are never logged. A replacement's `spawnCause` carries the previous retirement cause when known in the same host process; after a host restart it is `firstProcess`, not a guessed cross-process cause.
- `process_exit`: observed child-process exit code, separate from its retirement reason.

## Detached work and limits of coverage

Measurement runs once at stdout ingress, not again on response-observer/buffer replay. Metadata arriving between episodes is queued without bodies. The next attached episode receives these rows with original `at`/`startedAt` timestamps and `receivedDetached: true`; `startedEpisodeId` and `startedTriggerMode` retain the actual request-start origin (null if no episode was attached). This is **receiving-episode attribution**, not proof that the receiving episode triggered detached API work. If no episode attaches before retirement/exit, queued rows are flushed with null episode/trigger rather than falsely attributed to an ended episode.

Only complete message boundaries produce request rows; a killed/incomplete stream has no final request totals. CLI native/sub-agent and auxiliary calls can contribute to result totals outside the top-level request rows. Writer failure, disk exhaustion, SIGKILL or direct host `process.exit()` can lose asynchronous diagnostics; this is not an audit-grade billing receipt. Normal observed child exits and graceful Pi lifecycle retirements are recorded. No synchronous exit-file writer is added to contradict the nonblocking append contract.

No prompt text, tools' schemas/descriptions, tool arguments/results, result text, headers, environment or credentials are serialized. Projection accepts only the named metadata fields; unknown usage/envelope fields are discarded. The existing keepalive defaults and behavior are unchanged; only its false disk-resume comment is corrected.

## Proof

`tests/request-ledger.test.ts` drives the shipped adapter using the hand-written synthetic `multi-cycle-episode.jsonl` stream. It proves all three request rows, 1h/5m splits, separate result/model totals, nested exclusion, handoff/turn reuse, emitted and absent utilization, buffered attribution, exact keepalive/lifecycle/inactivity/exit reasons, existing-file permissions, seeded body rejection and seeded double-count rejection. The handoff variant renames the synthetic ToolSearch call to a Pi-proxied tool; the cumulative-follow-up/rate-utilization cases explicitly enrich the synthetic frames. No fixture test spends subscription tokens.

For a live proof use Pi's documented extension path: `pi -ne -e /absolute/path/to/package/index.ts --model pi-claude-cli/claude-sonnet-5-5 -p ...`, in a disposable workspace with `XDG_STATE_HOME` set to a temporary directory. Limit the task itself to one Pi read tool call. Use the documented one-shot `PI_CLAUDE_CLI_KEEPALIVE_MS=0`; this changes only the proof invocation, not production defaults. Inspect Pi's tool-call/result events and compare the **request-only** sum to the separately retained CLI result `usage` and main-model cumulative snapshot, reporting any auxiliary-model difference explicitly.
